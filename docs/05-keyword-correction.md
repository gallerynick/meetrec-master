# 05 · 关键词优先识别规格（核心差异化）

> 本项目的技术核心。**四阶段「基线锚定 + 定向重解码」架构**。
> 设计第一原则：**热词效果做满，普通文本准确率零退化**。

---

## 1. 目标、原则与非目标

### 1.1 目标

| # | 目标 | 度量 |
|---|---|---|
| G1 | 人名 / 产品名 / 术语被识别为关键词的正确写法 | 关键词召回率 ≥ 90% |
| G2 | **热词对普通文本零副作用** | 普通文本 WER 退化 **= 0**（架构性保证，见 §2.3） |
| G3 | 所有自动改动可追溯、可撤销 | 每条改动有记录，支持一键撤销与逐条撤销 |
| G4 | 用户能看见关键词在哪里、被改过哪里 | UI 高亮 + 角标 |
| G5 | 全链路离线 | 无任何网络调用 |
| G6 | 热词机制可持续运营 | 命中率反馈闭环，引导用户补充别名 |

### 1.2 三条设计原则

1. **锚定原则**：普通文本必须来自一个**从未注入热词**的基线转写。这样热词副作用在架构上被隔离，而不是靠阈值去"尽量降低"。
2. **局部增强原则**：热词偏置只在**候选区域的短音频片段**上施加。片段越短，initial_prompt 在解码上下文中的占比越高，偏置效果越强 —— 这是比全局注入更强、而不是更弱的做法。
3. **证据合并原则**：基线与重解码两次结果**必须比对择优**，不满足采用条件的改动一律丢弃。宁缺勿滥。

### 1.3 非目标

- 不训练 / 微调 ASR 模型（成本与数据要求超出范围）。
- 不追求 100% 正确 —— 因此必须提供人工校对与撤销。
- 不做说话人区分，因此关键词上下文不做说话人绑定。

## 2. 总体架构：四阶段

```text
                 ┌─────────────────────────────────────────┐
                 │ Stage 1  全局基线转写（不注入热词）        │
                 │   目的：为普通文本建立零污染锚点            │
                 └──────────────────┬──────────────────────┘
                                    ▼
                 ┌─────────────────────────────────────────┐
                 │ Stage 2  关键词缺口分析                    │
                 │   命中率统计 + 三路候选区域定位             │
                 │ Stage 3  定向重解码（核心创新）            │
                 │   片段抽取 ±3s → 分组注入 initial_prompt   │
                 │   → 双结果择优合并                         │
                 └──────────────────┬──────────────────────┘
                                    ▼
                 ┌─────────────────────────────────────────┐
                 │ Stage 4  后处理纠错（兜底）+ 别名精确匹配    │
                 └──────────────────┬──────────────────────┘
                                    ▼
                 CorrectionRecord[] → UI 高亮 / 落盘 / 命中率反馈
```

**为什么不是「全局注入 + 后处理」两步？**

只把关键词拼进 initial_prompt 让整段音频转写一次，存在两个无法解决的问题：

1. **偏置衰减**：initial_prompt 影响的是解码起点附近的上下文。长音频中段出现的人名，偏置已大幅衰减，召回率不可控。
2. **全局副作用**：注入的文本参与整个解码过程的注意力计算。关键词越多、prompt 越长，对普通文本的干扰越明显 —— 这正是「为了热词而降低识别正确率」的来源。

四阶段架构把这两个问题分别消灭：**基线不受污染**（解决副作用），**片段短所以偏置强**（解决衰减）。

### 2.1 阶段独立性

| 阶段 | 可否关闭 | 说明 |
|---|---|---|
| Stage 1 基线 | ❌ 不可关 | 是整个架构的锚点 |
| Stage 2 缺口分析 | ✅ 可关 | 关闭后跳过定向重解码 |
| Stage 3 定向重解码 | ✅ 可关 | 关闭后热词仅靠 Stage 4 后处理 |
| Stage 4 后处理纠错 | ✅ 可关 | 关闭后不做文本替换 |

设置中对应三个开关，便于 A/B 评测与故障隔离。

### 2.2 成本模型

| 阶段 | 计算量 | 说明 |
|---|---|---|
| Stage 1 | 100% 音频 | 一次完整转写 |
| Stage 2 | 可忽略 | 纯文本计算，1 小时转写 < 100 ms |
| Stage 3 | **5–15% 音频** | 只重转写候选区域 |
| Stage 4 | < 1% | 纯文本计算 |

**总耗时 ≈ 基线转写 × 1.10**（而非 ×2），因为 Stage 3 只跑局部片段。

### 2.3 零副作用的架构性保证

普通文本来自 Stage 1 基线，**从未被任何热词参数处理过**，因此：

```text
普通文本 WER（有热词流程） = 普通文本 WER（无热词流程） = 基线 WER

退化 = 0（严格等式，不依赖阈值调参）
```

这是与「全局注入 + 阈值控制」本质不同的保证方式：后者是概率性缓解，前者是结构性隔离。

## 3. Stage 1 · 全局基线转写

### 3.1 参数

| 参数 | 值 |
|---|---|
| initial_prompt | **None（不注入）** |
| language | 显式指定（zh / en） |
| word_timestamps | True（Stage 2/3 需要词级概率与时间戳） |
| vad_filter | True |
| beam_size | 5 |
| compute_type | int8（默认） |

### 3.2 输出

- segments：id / start / end / text / avg_logprob / no_speech_prob / words
- words：start / end / word / probability
- 基线原文 raw_text（用于后续所有比对的锚点）

### 3.3 约束

1. 基线转写结果**只读**，后续阶段不得原地修改，只产出「区域级替换建议」。
2. 基线参数快照写入 meta.json，便于复现。
3. 用户切换 ASR 模型必须重新跑 Stage 1。

---

## 4. Stage 2 · 关键词缺口分析

目标：找出「音频里可能说过、但基线没识别对」的候选区域，把 Stage 3 的计算量压到最小。

### 4.1 关键词命中率统计

```text
对每个关键词 K：
  hits(K) = 基线文本中精确匹配 K 的次数
  命中率 = hits(K) / 用户预期的出现次数（未知时记为「未命中/已命中」二值）

未命中关键词集合 = 库中 enabled 且 hits(K) == 0 的关键词
```

### 4.2 三路候选区域定位

#### R1 · 低置信区域

| 条件 | 阈值（平衡档） |
|---|---|
| segment.avg_logprob | < -0.70 |
| 覆盖词平均 probability | < 0.75 |
| 词 probability 缺失 | 视为 0.5，纳入候选 |

#### R2 · 疑似变体区域

在基线文本中用模糊匹配寻找「接近关键词但没写对」的片段：

```text
对每个未命中关键词 K：
  在基线文本中找候选片段 S（4.2 分词 + 近邻合并）
  若 相似度(S, K) ≥ 0.62（低于 Stage 4 的替换阈值，这里只要「值得复核」）
     → S 所在 segment 进入候选
```

这一步是召回率的关键：Stage 3 重解码时，模型有机会在带偏置的条件下重新听到这段音频。

#### R3 · 称呼与开场区域（可选，默认开启）

| 条件 | 阈值 |
|---|---|
| 会议前 60 秒 | 全量纳入（人名、议程常在开场出现） |
| 长静音（> 4 秒）后 5 秒内 | 纳入（话题切换处常有人名） |
| 关键词所在分组的「已知高频位置」 | 用户可手动标记，纳入 |

### 4.3 区域合并与预算控制

```text
1. 排序：按 segment.avg_logprob 升序（最不可信优先）
2. 合并：相邻候选 segment 合并为一个区域（间隔 ≤ 2 秒则合并）
3. 上下文扩展：每个区域前后各扩展 3 秒音频
4. 预算裁剪：
   - 总重解码音频时长 ≤ 基线音频时长的 15%（可配置，10%–30%）
   - 单区域时长 ≤ 60 秒（超过则按段切分）
   - 超出预算的低优先级区域丢弃，并在日志中记录被丢弃数量
5. 去重：同一音频区间只处理一次
```

### 4.4 跳过条件

| 情况 | 行为 |
|---|---|
| 关键词库为空或全部禁用 | 跳过 Stage 2/3/4，直接返回基线 |
| 所有关键词都已命中 | 跳过 Stage 3（无缺口），仅跑 Stage 4 做兜底校验 |
| 候选区域为空 | 跳过 Stage 3 |
| 音频时长 < 30 秒 | 不扩展上下文，避免越界 |

## 5. Stage 3 · 定向重解码（核心）

### 5.1 原理

```text
基线片段（10–30 秒音频，无偏置）  ──┐
                                     ├─▶ 择优合并 → 最终文本
重解码片段（同一段音频，带偏置）    ──┘
```

**为什么局部重解码比全局注入更强**：initial_prompt 作为「前文」参与注意力计算。当待转写音频只有 15 秒时，prompt 在总上下文中的占比显著高于 1 小时音频，偏置强度更高。也就是说：**同样的关键词列表，注入到短片段上的效果强于注入到整段音频上**。

### 5.2 分组注入

不是把所有关键词塞进一个 prompt，而是**按分组相关性强弱注入**：

```text
对每个候选区域 R：
  1. 统计 R 的基线文本中已命中的关键词所属分组
  2. 计算各分组的相关度 = 该组关键词在 R 中命中数 + 该组未命中关键词的近似命中数
  3. 按相关度降序选取分组，累计注入直到达到预算上限
  4. 若所有分组相关度都极低 → 注入优先级最高的 1–2 个分组（保底）
```

**收益**：预算相同的情况下，与当前音频片段更相关的关键词获得偏置，无关关键词不占用预算。这直接降低副作用、提高召回率。

### 5.3 Prompt 构造

**预算**（按字符计，中文）：

| 项 | 值 |
|---|---|
| 总预算 | 260 字符 |
| 模板固定开销 | 40 字符 |
| 关键词可用字符 | 220 字符 |
| 单次注入关键词数上限 | 120 条 |

**模板**：

中文：

```text
会议中提到的关键词有：{kw_list}。请用这些准确写法记录。
```

英文：

```text
Keywords mentioned: {kw_list}. Use these exact spellings.
```

**排序**（稳定多级降序）：分组顺序 → keyword.priority → 历史命中频次 → 长度 → 原文。

**截断**：按排序累加，加入下一条会超预算则停止。被截断的不报错，记日志 + UI 轻提示。

**硬失败**：预算降至 60 字符以下仍容纳不了任何关键词 → 抛 KeywordPromptOverflowError。

### 5.4 重解码参数

| 参数 | 值 | 与基线的差异 |
|---|---|---|
| initial_prompt | 按 5.3 构造 | ✅ 注入 |
| language | 同基线 | 同 |
| word_timestamps | True | 同 |
| beam_size | **10**（提高，重解码值得多花算力） | ⬆ |
| best_of | 5 | 同 |
| temperature | (0.0, 0.2, 0.4, 0.6, 0.8) | 略收窄 |
| condition_on_previous_text | False（片段独立，避免跨片段污染） | ⬇ |
| vad_filter | False（片段短，VAD 可能整段判静音） | ⬇ |

### 5.5 择优合并规则

对每个区域 R，得到 baseline_text 与 redecode_text，按以下规则决定最终文本：

| # | 规则 | 说明 |
|---|---|---|
| D1 | **关键词增益优先** | 若 redecode_text 包含 R 的目标关键词，而 baseline_text 不含 → 进入 D2 |
| D2 | **质量不劣于基线** | redecode 的 avg_logprob ≥ baseline 的 avg_logprob - 0.10 → 采用 redecode |
| D3 | **差异度限制** | 两者归一化编辑距离 ≤ 0.50 → 采用 redecode；否则视为「重解码跑偏」，保留 baseline |
| D4 | **无增益则不动** | redecode 未引入新关键词 → 保留 baseline |
| D5 | **全部失败** | R 的所有规则都不满足 → 保留 baseline，记录一条「已复核，未采用」日志 |

**保守取向**：D2 与 D3 是双重保险。logprob 保证语义质量不退化，编辑距离保证不把一段正常的讨论改写成别的内容。

### 5.6 示例

基线（无偏置）：

```text
[02:14] 然后这个方案张一鸣他们会怎么看，还有 CTranslate 这边的性能……
```

缺口分析：关键词「张一鸣」已命中；「CTranslate2」未命中，基线中「CTranslate」相似度 0.87 → R2 命中 → 该 segment 进入候选。

重解码（beam=10，注入「CTranslate2、faster-whisper、MeetRec Master」）：

```text
[02:14] 然后这个方案张一鸣他们会怎么看，还有 CTranslate2 这边的性能……
```

合并判定：D1 通过（引入新关键词 CTranslate2）→ D2 通过（logprob 差异 -0.04）→ D3 通过（编辑距离 0.06）→ 采用。

## 6. Stage 4 · 后处理纠错（兜底）

Stage 3 处理「音频听不清」的场景；Stage 4 处理「听清了但写错了」的场景，尤其是 **initial_prompt 完全失效的同音替换**（如「张一鸣」→「章一鸣」，基线与重解码都写成「章一鸣」）。

### 6.1 关键词别名表（核心增强）

ASR 错误是**系统性、可预测**的：同一个词的错误写法几乎每次都一样。因此允许用户为关键词登记已知错误写法，走**精确匹配**而非模糊相似度。

```python
@dataclass
class Keyword:
    id: str
    text: str                          # 正确写法，如「张一鸣」
    aliases: tuple[str, ...] = ()      # 已知错误写法，如（"章一鸣", "张一明", "张易鸣"）
    group_id: str | None = None
    priority: int = 50                # 1–100
    enabled: bool = True
    note: str = ""
```

**别名的匹配规则**：

| 规则 | 说明 |
|---|---|
| 精确匹配优先 | 别名命中时置信度记为 1.00，直接替换，跳过所有相似度门控 |
| 大小写敏感 | 中文别名精确匹配；英文别名默认大小写敏感，可配置忽略 |
| 长度限制 | 别名长度 1–30 字符，与关键词一致 |
| 唯一性 | 同一库内别名不得与其他关键词或别名冲突；冲突时保存报错并指出冲突项 |
| 来源 | 手动添加，或从「未采用复核」与「歧义未校正」中一键登记（见 §11） |

**为什么别名是「热词做好」的关键**：相似度算法对短词与多音字天然不可靠（「张」和「章」拼音都是 zhang）。别名把不可靠的推断变成确定的映射，是成本最低、收益最高的一项。

### 6.2 候选生成

```text
对每个 segment 的 text：
1. jieba 分词得到 tokens（保留位置偏移）
2. 构造窗口：长度 1–4 的 token 序列拼接，形成候选片段 S
3. 剪枝（进入相似度计算前）：
   - len(S) 与 len(K) 比不在 [0.5, 2.0] → 丢弃
   - S 含标点 / 换行 → 丢弃
   - S 完全等于 K 或某别名 → 标记为已正确，丢弃
   - S 的字符集与 K 字符集无交集 → 丢弃
```

**性能预算**：单 segment ≤ 20 ms；1 小时转写纠错总耗时 ≤ 3 s。超限则降级为「仅长度 ±1 窗口」。

### 6.3 相似度度量

三个分数归一到 [0, 1]：

| 分数 | 计算方法 | 权重 |
|---|---|---|
| **拼音相似度** pinyin_sim | pypinyin 取 S 与 K 的拼音序列（含声调）；英文按字母比较。序列用 rapidfuzz.fuzz.token_sort_ratio 归一 | 0.50 |
| **编辑距离相似度** edit_sim | rapidfuzz.fuzz.ratio(S, K) / 100 | 0.30 |
| **长度相似度** len_sim | 1 - abs(len(S) - len(K)) / max(len(S), len(K)) | 0.20 |

```python
score = 0.50 * pinyin_sim + 0.30 * edit_sim + 0.20 * len_sim
```

**拼音权重最高的原因**：中文 ASR 错误绝大多数是**同音 / 近音替换**，拼音相似度直接命中这类错误；纯编辑距离对同音字完全无效（「张」与「章」距离为 1，但语义全错）。

### 6.4 门控条件（全部满足才替换）

| # | 条件 | 阈值（平衡档） |
|---|---|---|
| M1 | score ≥ 阈值 | ≥ 0.78 |
| M2 | 拼音相似度下限 | pinyin_sim ≥ 0.70（中文）；英文要求 edit_sim ≥ 0.80 |
| M3 | 长度比 | len(S) / len(K) 在 [0.6, 1.8] 内 |
| M4 | ASR 词概率门控 | 覆盖词平均 probability < 0.92（高置信则不动） |
| M5 | 单词长度保护 | len(K) ≤ 2 时要求 pinyin_sim ≥ 0.90 |
| M6 | 上下文保护 | S 前一个字是虚词（的 / 了 / 是 / 和 / 在）→ 阈值上调 0.05 |
| M7 | 唯一性 | 同位置多个关键词得分接近（差值 < 0.05）→ 不替换，标「歧义」 |
| M8 | 频次保护 | 同一关键词在同段被替换 > 3 次 → 后续不自动替换 |
| M9 | 区域一致性 | S 所在区域若已在 Stage 3 被采用重解码结果，M1 阈值下调 0.04（重解码已提供额外证据） |

### 6.5 强度预设

| 预设 | M1 阈值 | M4 概率门控 | M2 拼音下限 | 适用 |
|---|---|---|---|---|
| 保守 | 0.86 | < 0.88 | 0.78 | 正式纪要、法务场景 |
| **平衡（默认）** | 0.78 | < 0.92 | 0.70 | 日常会议 |
| 激进 | 0.70 | < 0.95 | 0.60 | 快速草稿、愿意人工校对 |

Stage 3 的合并规则（D2/D3）阈值**不随预设变化** —— 重解码的采用必须始终保守，因为它改动的是整段音频的文本。

### 6.6 禁止规则（任何预设都不放开）

1. **不跨标点**：候选片段不得跨越逗号、句号、问号、感叹号、分号、顿号、冒号、引号、括号。
2. **不跨句子边界**：不跨越 segment 边界。
3. **不跨换行**。
4. **不改数字**：S 含数字而 K 不含数字 → 不替换（防止「3 月」→「三月」）。
5. **不改专有符号**：含 % . / - 的片段不参与中文拼音纠错。
6. **不改已校正位置**：同一位置重复运行不叠加校正。
7. **不改基线外的文本**：Stage 4 只在 Stage 3 合并后的最终文本上工作。

### 6.7 算法伪代码

```python
def correct_region(final_text, keywords, policy):
    records = []
    best = {}
    # 别名精确匹配（优先，置信度 1.00）
    for kw in keywords:
        for alias in kw.aliases:
            for pos in find_all(final_text, alias):
                records.append(CorrectionRecord(
                    before=alias, after=kw.text, score=1.0,
                    match_kind="alias", reverted=False))
    # 模糊匹配（跳过已被别名覆盖的位置）
    for span in enumerate_spans(final_text):
        if span.covered_by_alias():
            continue
        for kw in keywords:
            s = score(span.text, kw)
            if not gates_pass(s, span, kw, policy):
                continue
            if s.score < best.get(kw, 0):
                continue
            best[kw] = s
    for span, s in resolve_conflicts(best):        # 区间不重叠 + M7 + M8
        records.append(CorrectionRecord(
            offset=span.start, length=len(span.text),
            before=span.text, after=best_kw,
            score=round(s.score, 4), match_kind="fuzzy",
            pinyin_sim=s.pinyin_sim, edit_sim=s.edit_sim,
            word_probs=tuple(probs),
            rule_version="2.0", policy=policy))
    return apply_records(final_text, records), records
```

### 7.1 CorrectionRecord

```python
@dataclass(frozen=True)
class CorrectionRecord:

    segment_id: int

    pinyin_sim: float | None
    edit_sim: float | None
    word_probs: tuple[float, ...]

    redecode_logprob: float | None
    baseline_logprob: float | None
    rule_version: str             # 算法版本，便于回放
    policy: str                   # conservative / balanced / aggressive
    created_at: str               # ISO8601 UTC
    reverted: bool = False
```

### 7.2 撤销模型

| 操作 | 行为 |
|---|---|
| 逐条撤销 | 点角标 → 该 record 标记 reverted=true，文本还原 before |
| 按阶段撤销 | 「撤销全部重解码」/「撤销全部纠错」分开操作 |
| 全部撤销 | 一键回到 Stage 1 基线原文 |
| 重新校正 | 用当前关键词库与预设重跑 Stage 2–4；旧记录全部标记 superseded |
| 保存 | 记录随转写落盘到 transcript.json 的 corrections 字段 |
| 导出 | 合集导出中改动位置标注「已校正」，附录列出改动清单 |

### 7.3 持久化保证

- transcript.json 同时保存 raw（Stage 1 基线）与 text（最终文本）。
- 用户手动编辑后 offset 可能失效 → 保存 text_edited 标记；再次校正时以 raw 为基准重算，并提示「转写已被手动编辑，校正将基于最新文本重新计算」。

## 8. 命中率反馈闭环

热词的效果不是配置一次就完事，需要持续运营。系统自动收集反馈并引导用户改进关键词库。

| 信号 | 含义 | 系统动作 |
|---|---|---|
| 关键词连续 3 次会议未命中 | 可能发音特殊或写法不常见 | 关键词库中标记「疑似低召回」，提示「建议添加别名」 |
| Stage 3 重解码已复核但未采用（D2/D3 不通过） | 音频听不清，非热词问题 | 计入「音频质量受限」计数，超过 5 次提示改善录音环境 |
| Stage 4 标「歧义」（M7） | 两个关键词读音相近 | 在歧义处提示用户选择，并把用户的纠正写入别名 |
| 别名被使用 | 别名有效 | 统计别名命中次数，在库中显示「已节省 N 次手动纠正」 |
| 用户撤销某条纠错 | 该规则在该场景误判 | 记录被撤销的 (K, before) 组合；同一组合被撤销 2 次 → 自动建议加入「不校正名单」 |

**「不校正名单」**：用户可登记「这些词不要自动改」，Stage 4 直接跳过。避免个别词反复误改损伤信任。

### 8.1 报表

设置 → 关键词 → 「使用统计」页展示：

- 关键词总数 / 启用数 / 别名数
- 近 10 次会议的平均召回率
- 每个关键词的命中次数、别名命中次数、被撤销次数
- 建议优化列表（低召回关键词、被撤销组合、歧义对）

## 10. 评测口径（验收依据）

### 10.1 指标定义

设真值标注中第 i 个关键词在音频中真实出现次数为 gt_i，最终文本中该关键词出现次数为 hit_i。

```text
关键词召回率 Recall = Σ min(hit_i, gt_i) / Σ gt_i                    目标 ≥ 90%
普通文本 WER 退化 = 0（架构性保证，见 §2.3）                          必须严格成立
整体 WER           = 最终文本 vs 真值转写的词错误率                    目标 ≤ 基线 WER
自动改动精确率 Precision = 人工判定正确的改动数 / 改动总数              目标 ≥ 90%
误改率             = 人工判定错误的改动数 / 高置信词总数                目标 ≤ 1%
Stage 3 采用率     = 被采用的区域数 / 候选区域数                       观测项，无硬性目标
Stage 3 增益率     = 采用后召回率提升的区域数 / 采用数                  目标 ≥ 70%
```

### 10.2 样本要求

| 项 | 要求 |
|---|---|
| 段数 | 3 段 |
| 单段时长 | 3–5 分钟 |
| 关键词数 | 约 50 个（人名 ≥ 15、产品名 ≥ 10、术语 ≥ 25） |
| 内容 | 中文会议录音，含正常语速与部分口音 |
| 标注 | 每段提供 ground_truth.json（关键词真值出现次数 + 参考转写文本 + 普通文本参考段） |

### 10.3 评测组合

必须跑 **5 种组合**用于归因（而非 4 种，新增「基线」对照组）：

| # | 组合 | 用途 |
|---|---|---|
| 1 | 仅基线（Stage 1） | 对照组，得到基线 WER 与召回率下界 |
| 2 | 基线 + Stage 3 | 定向重解码的独立贡献 |
| 3 | 基线 + Stage 4 | 后处理纠错的独立贡献 |
| 4 | 全四阶段（默认） | 验收口径 |
| 5 | 全局注入 + Stage 4（旧方案，仅对比用） | 证明四阶段架构的优势 |

**对比第 5 组是必须的**：只有跑过旧方案，才能量化「四阶段架构把 WER 退化从 X% 降到 0%」的实际收益。

### 10.4 评测脚本要求

- 脚本：tests/accuracy/run_accuracy.py
- 输出：Markdown 报告（每段 × 每指标 × 每组）+ 明细（每个关键词的 hit / gt）
- 报告必须记录：模型、compute_type、关键词数量、别名数量、注入字符数、候选区域数与总时长占比、纠错预设
- 断言门：组合 4 的 Recall ≥ 0.90 且普通文本 WER 退化 == 0，否则 CI 失败

## 11. 边界情况与失败模式

| 情况 | 行为 |
|---|---|
| 关键词库为空 | 跳过 Stage 2–4，直接输出基线；UI 提示「未配置关键词」 |
| 关键词全部被预算截断 | 记日志 + 轻提示，不阻断 |
| 英文关键词混入中文转写 | 拼音分数退化为编辑距离，权重重新归一到 edit 0.7 / len 0.3 |
| 中英混写关键词（如 MeetRec Master） | 按空格切分子词分别打分，取最高分 |
| 关键词含数字（如 v1.2） | 仅允许与含数字的候选匹配（禁止规则 4） |
| 同音歧义（张伟 / 张维） | M7 触发 → 不替换，标歧义，引导用户选择 |
| ASR 概率为 None | 视同 0.5，不阻断 |
| jieba 分词失败 | 降级为字符 2-gram / 3-gram 窗口扫描 |
| 拼音库缺失字 | 该字回退为原字比较 |
| Stage 3 重解码比基线更差 | D2/D3 拦截，保留基线（这是保守取向的核心价值） |
| 候选区域超过预算 15% | 按优先级裁剪，日志记录丢弃数 |
| 音频极短（< 30 秒） | 不扩展上下文，Stage 3 仍执行 |
| 别名与关键词冲突 | 保存时阻断并指出冲突项 |
| 用户手动编辑后重跑 | 以 raw 为基准重算，提示 offset 已重算 |
| Stage 3 片段越界 | 音频起止边界截断，不补零 |
